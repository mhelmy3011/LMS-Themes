# English / العربية editions

All four themes and the family hub have pre-rendered English LTR and Arabic RTL editions. Use the **العربية / English** control in the header or mobile drawer. It is a real link, styled as a control, because it navigates to the same page in another language; it remains usable without JavaScript.

## Routes and switching

- Existing English URLs are unchanged: `dist/courses/<slug>/index.html`.
- Arabic mirrors use `dist/ar/courses/<slug>/index.html`. The hub also has `ar/index.html`.
- There are **362 English theme routes and 362 Arabic mirrors**, plus four specimen tools per language. Each distribution also includes 28 Arabic HTML document companions: **844 generated HTML files across the four distributions, plus two family hubs**.
- Native links work from a static server or `file://`. Internal navigation, cross-theme links, images, scripts, calendars and downloads resolve to the appropriate edition with explicit relative file URLs.
- The current query and fragment are retained when switching with JavaScript. Search queries are not machine-translated. Scroll coordinates, partially completed forms and open drawers are not transferred across documents.
- `wa-language-v1` stores only `en` or `ar` in local storage. An early, guarded head script can select the Arabic peer before the English document paints. Returning to English sets `?lang=en` so a stored Arabic preference cannot trap a visitor in Arabic. Storage denial is caught; direct links remain usable.
- Saved course IDs, followed educator IDs and lesson completion flags are shared between editions. Form answers, passwords, lesson notes and other personal details are not persisted or copied into URLs.
- Supporting browsers use a short 140ms native cross-document view transition. Navigation is still ordinary navigation in other browsers. View-transition opt-in and content motion are disabled for reduced-motion users. Critical hero text is painted immediately, not hidden behind an entrance animation.

Deploy the **whole `dist/`**, including its `ar/` and localized asset directories. Serving only `dist/ar/` breaks shared relative assets. No middleware, browser translation service, client-side catalogue request or framework is needed.

## Translation sources

| File | Responsibility |
|---|---|
| `shared/locales/ar.json` | Curated Arabic copy for content, chrome, forms, explanations, policies, metadata and runtime messages |
| `shared/lib/i18n.mjs` | Build-time text/attribute/schema localization, route mapping, locale head, native controls and small runtime message maps |
| `shared/css/rtl.css` | Arabic type, line height, joining-safe spacing, selected directional icons and bidi isolation |
| `shared/locales/ar-art-labels.json` | Reusable, pre-shaped glyph outlines and label recipes for Arabic SVG artwork |
| `shared/lib/arabic-downloads.mjs` | Shared Arabic document sections, printable HTML, source fingerprints and PDF release validation |
| `shared/downloads/ar/manifest.json` | Required PDF release inventory, source hashes, byte hashes, sizes and page counts |

Add English source copy and its Arabic counterpart together. Whole sentences and parameterized templates are preferred over fragment composition. IDs, slugs, form values, email addresses, URLs, code examples, technical identifiers and token keys are kept stable. Arabic token-download descriptions are localized without changing their machine-readable values.

The runtime ships only the literal `tr('…')` messages used by a theme, not the full translation catalogue. `WAI18n` supplies localized messages and cached number/USD formatters. Dates use `Intl.DateTimeFormat` with `ar-EG`; event instants and calendar UIDs do not change with language. Timezones, timers, email/URL/number fields and code are isolated where their reading direction differs from the page.

### Typography and artwork

- Local **Noto Sans Arabic 400 and 700** provide connected Arabic shaping. The two WOFF2 files total approximately **74.3 KiB**. English does not preload them; Arabic replaces the Latin preload. English retains local Lexend and JetBrains Mono, and technical code in Arabic may still use the local Latin monospace face.
- The authentic SIL OFL is included at `shared/fonts/OFL-NotoSansArabic.txt`. The commercial brand-book fonts are not distributed.
- Do not add letter spacing to Arabic or split Arabic words into animated character spans. Aero's Arabic heading bypasses the Latin character effect.
- Standalone SVGs cannot rely on a parent page's fonts. Arabic labels are shaped at release time with HarfBuzz and bidi processing, then emitted as compact reusable vector glyphs. No font is embedded in every image; no Arabic letters are reversed. Meaningful SVG titles/descriptions remain Arabic text for assistive technology.
- Edit the original drawing helpers and translations, not generated outlines or `dist/` copies. Normal builds need only Node and the checked-in release assets.

## Documents and metadata

Each theme includes 16 three-page Arabic syllabi and 12 four-page Arabic workbooks. The same translated section model produces readable/printable HTML companions, linked beside Arabic PDF downloads. Fonts are embedded and Chromium emits language/tag information. **These checks are not PDF/UA certification**; extracted Arabic text order can vary by PDF reader. Prefer the HTML alternative when needed.

Arabic `.ics` files keep exact UTC instants and stable UIDs, use Arabic event copy, and retain RFC 5545 escaping and UTF-8 byte folding. The pricing CSV uses a UTF-8 BOM, Arabic labels and unchanged spreadsheet formulas. The specimen tool has an Arabic sample, controls and local Arabic type.

HTML has the correct `lang` and `dir`, translated titles/descriptions and accessible attributes. Both editions have paired `hreflang` links and language-appropriate Open Graph locale/cards. When `WA_SITE_URL` is configured, canonical URLs, public sitemap entries and relevant structured-data URLs point at the appropriate edition. Demo utilities remain `noindex`. Configure a base URL for a single theme, not the multi-theme demo collection.

## Routine builds and checks

```sh
WA_I18N_REPORT=1 WA_I18N_STRICT=1 npm run build
npm test                 # Node tests + structural inventory + bilingual release gate
npm run test:i18n         # bilingual-only dependency-free audit
npm run serve            # port 4173
npm run test:arabic       # optional browser / RTL / axe / interaction / fallback audit
npm run test:browser      # English regression
npm run test:release      # native Arabic downloads, media, real fonts and forced-color focus
npm run test:perf         # both languages, three throttled lab samples per theme; fails on target misses
```

The strict build reports missing text/art labels under `.cache/i18n/build-report.json`. `test:i18n` checks every locale peer, visible copy/accessible attributes against a small technical allowlist, local references, SVG glyph references, fonts, localized calendars/CSV/JSON, PDF release freshness and combined Arabic CSS/JS budgets. It is a coverage check, **not proof of editorial fluency or accessibility conformance**.

Browser tooling is optional and ignored by Git:

```sh
npm install --prefix .cache/qa --no-save --no-package-lock \
  playwright-core@1.64.1 @sparticuz/chromium@153.0.0 @axe-core/playwright@4.14.0
```

A system Chromium may be selected with `CHROMIUM_EXECUTABLE_PATH`. `WA_BROWSER_PACKAGES` selects a different optional package directory. `WA_TEST_URL` selects a running preview (include its trailing slash). Suites can be focused with `WA_QA_SUITE=routes,responsive,interactions,fallbacks`; the default is all suites. Performance supports `WA_PERF_LANGUAGES=en,ar`, `WA_PERF_THEMES=nova,atelier,aero,folio` and `WA_PERF_RUNS=3`; report non-default sampling explicitly.

## Refreshing release assets

Ordinary builds do not install a browser or Python packages. PDF copying **fails closed** when a required release is missing, stale or corrupt. Source fingerprints include translated document data, stable printable HTML and font bytes; a CSS/font change to the printable template requires re-export, not just a text change. PDF byte hashes are also verified before copying.

When document text, printable styles or Arabic fonts change:

```sh
npm run downloads:arabic   # optional Chromium release helper; produces 28 PDFs + manifest
npm run build
npm run test:i18n
```

When drawing labels or their translations change, install optional shaping tools and rebuild the atlas:

```sh
python -m pip install --target .cache/i18n/python 'fonttools[woff]' uharfbuzz python-bidi
# Build first to refresh English SVG/inline-label inputs; during a deliberate
# atlas update omit WA_I18N_STRICT until the new atlas has been generated.
npm run build
npm run artwork:arabic
WA_I18N_STRICT=1 npm run build
npm run artwork:social
WA_I18N_STRICT=1 npm run build
npm test
```

`artwork:arabic` reads the generated English drawings, but shaping uses the checked-in local art font. `artwork:social` uses optional Chromium to produce real 1200×630 crawler-compatible PNGs. Required Arabic social PNGs are not silently skipped by the normal build. Commit the small release assets and manifest with their sources; keep optional tools, temporary HTML, parser rasters and browser reports in ignored `.cache/`.

Before production, have a fluent Arabic editor and real Arabic screen-reader users review the actual replacement content, pronunciation and task flows. Automated coverage does not replace that review or real-device/field-performance measurement. See [QA](QA.md) for executed evidence and limitations.
